# 架构与协作约定

## 产品架构

采用“通用核心 + 领域配置包”。Computer Vision 是第一个配置包，不建立独立的 CV 专用数据表或应用分支。

建议后续核心实体包括 Field、Venue、VenueEdition、Deadline、Qualification、Evidence 和 ChangeLog。会议与领域采用多对多关系，期刊与会议共享基础身份信息但保留类型差异。

## 首个纵向切片

- 使用 JSON 保存领域配置和会议种子数据。
- 使用 Node.js 标准库实现校验和测试，不安装依赖。
- 校验器同时提供可编程接口和命令行入口。
- 本轮不设计前端或数据库，避免扩大实验变量。

## 编排协议

任务状态为 draft、ready、in_progress、verifying、done、revise、blocked。

每个任务必须具备目标、上下文、允许修改路径、禁止事项、验收条件、验证命令和升级规则。执行结果必须列出实际变更、测试、偏差和不确定项。

同一问题最多由执行模型修复两轮；涉及公共契约变更、跨范围修改或来源冲突时，停止执行并交回强力模型重新规划。

## 扩展约束

- 新领域通过新增领域包接入。
- 新采集器必须实现统一的发现、抓取、规范化和校验边界。
- 自动采集结果先进入候选区，不直接覆盖正式数据。
